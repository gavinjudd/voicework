# Voicework implementation contract
Local-first personal writing calibration app. Python 3.9+ stdlib HTTP/SQLite backend; dependency-free ES module browser UI. Run python3 -m voicework at 127.0.0.1:8765. Default provider=offline (explicitly labeled heuristic rehearsal), optional provider=codex via local CLI configured by operator. Source is published under the MIT License in [gavinjudd/voicework](https://github.com/gavinjudd/voicework); local writing and databases remain separate. No real personal samples seeded. Direct teaching and practice require no samples.

## Layout
- `voicework/server.py`, `store.py`, `learning.py`: local API, reviewed samples, feedback and portable profiles.
- `voicework/discovery.py`, `discovery_jobs.py`: bounded extraction and persistent resumable scan queues.
- `voicework/context.py`: provisional context analysis and separate prior packets.
- `voicework/matching.py`: auditable whole-label aliases, context eligibility and retrieval diagnostics.
- `voicework/language.py`: editable contextual language lessons and focused-practice validation.
- `voicework/corrections.py`: atomic remembered corrections, source provenance, context scope and guarded undo.
- `voicework/quality.py`: blinded checks isolating one correction, independent meaning/effort ratings and input fingerprints.
- `voicework/evaluation.py`: blinded comparisons and immutable ratings, independent of training feedback.
- `voicework/provider.py`: explicit offline/Codex generation and context-analysis adapter.
- `web/`, `extension/`, `tests/`: app interface, deliberate Chrome capture/Docs collector, and verification.

## Records
Sample {id,title,text,source_type,source_path,source_url,status,context,held_out,created_at,fingerprint}. status=pending|confirmed|assisted|rejected. context={channel,audience,intent,stakes,relationship,scenario}; channel accepts short text, including unknown. Omitted manual context defaults to work; discovery jobs suggest provisional context when absent. Context is user editable and never confirms authorship. Only confirmed, non-held-out samples are positive style evidence. Sample limit 30k chars.
Round {id,context,focus,options:[{id:'a',text},{id:'b',text}],provider,status,created_at}; focus=mixed|vernacular|syntax|diction|rhythm, default mixed. Options are provider generated, offline clearly heuristic. Feedback {round_id,choice:'a'|'b'|'neither',edited_text,notes,presentation:{...}}; reads include the round's context, focus and alternatives. Preferred output NOT a genuine authored sample. Edits are feedback only. Presentation dimensions paragraph_length,structure,opening,signoff,emoji,detail; free text values. Contextual preferences learned from notes and structured choices. Preserve both chosen and rejected output for contrast.
Profile {confirmed_count,feedback_count,language_lesson_count,language_contexts:[{channel,count}],contexts:[{channel,count}],patterns:[{name,value,evidence_count}],preferences:[{context,notes,presentation,choice,edited_text,focus}],level,xp,next_milestone}. Lesson counts include enabled lessons only. XP measures contributions, never inferred accuracy. Holdout confirmed samples excluded from prompt/profile training; held_out bool on sample. Display coverage, not fake fidelity percentage.

LanguageLesson {id,context,dimension,guidance,preferred,avoided,enabled,created_at}. dimension=vernacular|syntax|diction|rhythm. Guidance is at most 2,000 characters; preferred and avoided wording at most 500 each; at least one must be nonempty. New lessons are enabled. Edit content/context/dimension, disable/re-enable, or delete. Lessons are explicit preferences, separate from samples, background priors and evaluation votes; they never assert authorship. Matching requires the same channel and a normalized whole-label match for every nonempty declared audience, intent, relationship and stakes. Explicit field-specific aliases in `matching.py` recognize equivalents such as coworker/colleague and request review/ask for feedback. Custom or qualified labels stay literal; channels are never aliased. Blank conditions are unrestricted; scenario is descriptive conditional guidance, not a retrieval filter. Enabled matching lessons enter calibrated prompts; exports include all enabled lessons with their declared contexts. No sample is required.

Prior {id,label,text,source,context,confirmed,created_at}. Text limit 4k; initially unconfirmed. Confirmed matching-channel priors are distinct prompt/reference material, never authored samples. Confirm/unconfirm or delete; replace the packet to revise its text. Raw JSON archives are rejected in this compact-prior lane.

Inference {context,rationale,uncertainties,authorship_signals,provider}. All six context fields, bounded explanation lists, explicit uncertainty and unverified-authorship notice. Preview only; applying context is a separate sample PATCH. Held-out samples cannot be sent for inference.

EvaluationCase {id,context,brief,options:[{id:'a',text},{id:'b',text}],provider,status,created_at,warnings}. Unrated cases expose neither candidate mapping nor candidate-specific warnings. Rated cases additionally expose mapping,choice,factual_issue,notes,rated_at,result. Choices are a|b|tie|neither; ratings are immutable. Evaluation data never enters practice feedback or language lessons. The same normalized context, brief, provider and neutral controls generate both candidates; only calibrated generation receives approved evidence/preferences/confirmed priors/enabled matching lessons. Mapping is randomized server-side.

DiscoveryJob {id,roots,status,scanned,added,duplicates,skipped,warnings,created_at,remaining,coverage}. status=paused|completed|cancelled. Persistent queue and directory cursors survive restart. Changed/unreadable sources produce warnings and require another scan for omitted material. Completed means the queue was consumed, not exhaustive coverage.

## Voice confidence checkpoints

GET /api/state also returns `voice_confidence`: `{label,completed,total:3,milestones:[{id,label,complete,detail}],evidence:{authored_samples,feedback,lessons,channels},validation:{rated_real,calibrated_wins,baseline_wins,ties,neither,factual_flags,distinct_briefs,channels,correction_checks},note,next_step}`. The bar is explicitly evidence readiness, never a writing-accuracy percentage or an inferred authorship score. It reports cumulative checkpoints: evidence saved; at least one rated Codex whole-profile comparison; at least three distinct normalized context/brief pairs across at least two known channels. Comparison completion does not imply positive results. Outcome counts remain visible, including losses and factual flags; historical results do not establish the quality of the current profile.

Authored evidence counts normalized unique confirmed, non-held-out text only. Saved practice preferences and enabled direct language lessons are separate ways to start evidence readiness. Pending, assisted, rejected and held-out samples never advance it as authored evidence. Unrated and offline comparisons do not count as real validation. Rated Codex correction checks have a separate count and do not advance whole-voice milestones. The confidence response contains aggregate metadata only, with no raw examples or unrevealed comparison mappings.

GET /api/language-lessons -> {language_lessons}.
POST /api/language-lessons {context?,dimension,guidance?,preferred?,avoided?} -> {lesson}; enabled=true. Reject unknown fields and require at least one nonblank content field.
PATCH /api/language-lessons/:id {context?,dimension?,guidance?,preferred?,avoided?,enabled?} -> {lesson}; nonempty partial patch. A supplied context replaces the previous context using the usual six-field normalization.
DELETE /api/language-lessons/:id {} -> {ok:true}.
Disabled lessons remain editable but are excluded from subsequent generation, exports and active contribution counts. Deletion removes the local lesson; previous drafts and downloaded exports remain separate copies.

## Remembered draft corrections

Draft editing is local to the browser until the user explicitly remembers a correction. Copy uses the revised draft. Context is captured with generation so a later change to the compose form does not silently change the correction's source context. Intensity controls are temporary; facts/meaning edits cannot become style lessons through this API.

POST /api/corrections {original_text,revised_text,guidance,preferred?,avoided?,context,scope,dimension?,kind:'style'} -> {correction,lesson}. Original/revised text is at most 30,000 characters and must differ. Guidance is required and at most 2,000 characters; preferred/avoided phrases at most 500 each. Dimension defaults to diction. Scope is similar|channel. Similar requires at least one nonempty audience, intent, relationship or stakes condition; channel explicitly clears narrower conditions. Save the correction and its enabled language lesson atomically. Neither becomes an authored sample.

GET /api/corrections -> {corrections}; GET /api/state also includes corrections. Status distinguishes active, undone, inactive, lesson_changed and lesson_deleted. Original/revised text and the lesson snapshot provide local provenance, not additional training examples.

POST /api/corrections/:id/undo {} -> {correction,lesson}. Disable only the linked lesson if its content still matches the saved correction; preserve all unrelated lessons. Repeated undo is safe. A later content edit causes a conflict instead of overwriting the edited lesson. History remains after undo; this is not a deletion operation.

## Correction quality checks

POST /api/corrections/:id/checks {context,brief} -> {case}. The selected correction must be active, unchanged and applicable to the requested context. Require a fresh brief rather than the original/revised source text. Both variants use identical current eligible evidence, other preferences, context, brief, model and neutral controls; only the selected correction lesson differs. This isolates one correction rather than restoring a complete historical profile. Randomize generation and display order independently. Save no case when either generation fails.

POST /api/quality-checks/:id/rate {choice,meaning,effort,notes?} -> {case,summary}. Choice is a|b|tie|neither. Meaning requires an a and b judgment of preserved|changed|unsure. Effort requires an a and b judgment of none|light|substantial. Ratings are immutable and never enter training. Candidate mapping and warnings remain hidden until rating, then previous/updated identify without/with the correction. Input provenance uses identifiers and fingerprints instead of additional raw sample snapshots.

GET /api/state includes quality_checks and quality_summary. Codex observations and offline rehearsal stay separate, as do voice preference, meaning problems and subjective editing effort. Checks do not automatically apply or undo teaching, assert factual correctness, or establish a writing-accuracy percentage.

QualityCase {id,correction_id,context,brief,options:[{id,text}],provider,model,status,created_at,warnings}. After rating it also contains mapping,choice,meaning,effort,notes,rated_at,result,observations:{previous:{meaning,effort},updated:{meaning,effort}},controls,provenance. Unrated responses never expose mapping, provenance or candidate-specific warnings. QualitySummary {total,unrated,rated_real,previous_wins,updated_wins,ties,neither,meaning_issues,meaning:{previous:{preserved,changed,unsure},updated:{preserved,changed,unsure}},effort:{previous:{none,light,substantial},updated:{none,light,substantial}},offline_count,rated_offline,per_correction:[{correction_id,...counts}]}. Outcome counts describe rated Codex checks only; offline participation is counted separately.

GET /api/priors -> {priors}.
POST /api/priors {label,text,source?,context?} -> {prior}; unconfirmed.
PATCH /api/priors/:id {confirmed:bool} -> {prior}.
DELETE /api/priors/:id {} -> {ok:true}.
Confirmed priors are appended to the portable export separately from authored samples.

POST /api/evaluations {context,brief} -> {case}; two sequential generations, with no case saved if either fails or changes provider.

Only rated Codex cases enter real-model counts. Offline counts are rehearsal. Wins and factual flags are separate observations, not accuracy or factuality certification.

## Document revision intent

Document controls additionally accept `revision: rewrite|copyedit` (default `rewrite`); message endpoints reject it. The browser persists only these known values and changing intent invalidates previous checks. Rewrite mode applies the differences in relevant preferred/avoided pairs to sentence construction, diction and pacing; copyedit mode retains expression for local corrections. Both retain complete meaning, protected blocks, quotations, numbers and uncertainty. `length: auto` permits natural expression, while `preserve` retains approximate block length without locking syntax. Current requests and specific preferences take precedence; liked third-party references are partial supporting evidence, not whole-style targets.

Document results include `revision_summary: {mode,source_words,draft_words,retained_source_words,notice}`. Counts use case-insensitive word-token matching across the document; they describe wording retained, not personalized fit or an edit quota. Review may identify `copyediting_only` when a specific supplied voice preference is still unmet; retention alone is not a quality verdict. No generated draft, review, or diagnostic updates training records.

In rewrite mode, a complete semantic review with actionable voice findings can trigger one bounded targeted revision of the affected prose sections. The source and frozen profile stay fixed, and a complete new review follows. No loop repeats beyond that pass. A failed or incomplete revision review, or a newly reported content issue, retains the initial complete draft and original findings. Copyedit mode and review-only requests do not invoke this pass. `revision_passes` reports 0 for offline rehearsal, 1 for the initial live generation, or 2 after an accepted repair. Missing authored examples and wording overlap alone never trigger repair.

Frozen document inputs include `source_voice_phrases`: up to twelve unique, short applicable lesson `preferred` expressions already present in source prose (2–16 words, at most 120 characters, no multiline templates). They carry lesson IDs, not authorship claims. These are review anchors, never exact-word requirements. Absent phrases, mismatched/disabled lessons, protected-only text and whole preferred paragraphs do not create anchors. Formal register withholds this check and reports `formal_override`; overflow is reported rather than implying full coverage. Capitalization and whitespace changes count as retained wording. Rephrasing or relocation prompts review of the quality in its original section, with fresh equivalent wording allowed. The aspect-review contract below replaces lexical-loss findings. Repair retains source block separators. No phrase from a reference or example is inserted merely to demonstrate style.

## Context retrieval

Stored labels and correction fingerprints are never rewritten by matching. Case and repeated whitespace are normalized transiently. Lesson conditions are conjunctive; a missing requested field cannot satisfy a populated lesson condition. Unknown/unconfirmed labels remain literal lesson conditions rather than becoming unrestricted rules. Scenario text stays conditional guidance, not an enforced lesson gate.

An explicitly declared `long-form writing` lesson (also `long form writing` or `longform writing`) has one-way inheritance into the finite nonfiction format set in `LONGFORM_LESSON_CHANNELS`: technical articles, articles, essays, reflective essays, project articles/case studies, blog posts and the writer's personal website (`personal website`, also `personal site`, `personal website copy`, `portfolio website`, `portfolio site`; a bare `website` stays literal), including the listed long-form variants. On a personal website these defaults govern prose, not the length of short labels, captions or entries. No suffix stripping or keyword matching occurs. All other populated lesson conditions remain required. Specific lessons do not inherit back into the broad channel or sideways into other formats. Samples, feedback and priors retain strict channel matching. Routing reports `explicit_longform_lesson_scope` only for supplied enabled lesson contexts; candidates distinguish this scope from equivalent channels. The provider treats these lessons as defaults subordinate to specific preferences and explicit register. Disabled/undone lessons remain excluded.

Authored examples and practice feedback use the same relevance policy. Populated, known audience, relationship or stakes conflicts reject a candidate. A different intent may retain useful same-audience evidence but reduces rank. Selection requires sufficient structured overlap or multiple informative scenario words; shared stakes, generic wording and unknown placeholders alone do not qualify. Scenario-only matches with opposite negation are excluded. A channel-only fallback is available only when the request has no other context. Unknown channels supply no authored-example/feedback evidence, lessons or priors. Custom channels match only themselves unless they belong to an explicit channel alias family. Limits remain six samples and twelve feedback records.

`explain_context_match(actual, requested)` reports eligibility, score, matching/conflicting fields and informative scenario overlap for local inspection. The score orders eligible references; it is not voice confidence or factual accuracy. The finite alias table is intentionally conservative, not general semantic understanding. Provider entry points repeat eligibility checks; drafts, practice, whole-voice evaluations and correction checks share the same selection rules. Priors retain their separate confirmed, same-channel contract.

## Provider contract
Provider(mode='offline'|'claude'|'codex'|'anthropic',model=None,timeout=240,executable=None,endpoint=None).available() -> bool, generate_round(context:dict,evidence:list,preferences:list,focus='mixed')-> dict {options:[{id,text},{id,text}],provider:string,warnings:list}; generate_draft(context,brief,controls,evidence,preferences)->dict {text,provider,evidence_ids,warnings}; infer_context(sample)->Inference. Raise ValueError on failure, never silently switch provider. Resolve the executable from `--codex-bin` / constructor `executable`, then `VOICEWORK_CODEX_BIN`, then `codex` on PATH. `available()` means the CLI executable exists, not successful login, model compatibility or generation.

Offline is deterministic rehearsal and heuristic context inference. Focused offline comparisons use fixed contrasts; they do not semantically apply language lessons or demonstrate learned voice. Codex generation receives supplied confirmed non-held-out examples, contextual feedback, confirmed matching-channel priors and enabled matching language lessons. Lessons enter a separate `language_lessons` prompt field; baseline evaluation receives none. Deliberate context analysis can send one unconfirmed non-held-out candidate as analysis material. Outputs use strict schemas. No hidden desktop chat/memory access or model weight training is assumed. The default model is gpt-6-astra, requested with xhigh reasoning. A synthetic live draft passed with the app-bundled CLI 0.162.0-alpha.17.2. PATH's CLI 0.137.0 rejected Astra as requiring a newer CLI; it was not an authentication failure. These are observed compatibility results, not a universal minimum-version specification or a writing-accuracy result. See README for this Mac's explicit executable path and VERIFICATION.md for recorded checks.

Claude mode (`--provider claude`, default claude-opus-5-5) runs `claude -p --safe-mode --output-format json --json-schema <_schema(task)> --model M --tools "" --disallowedTools mcp__* --strict-mcp-config --disable-slash-commands --no-session-persistence --permission-mode dontAsk --system-prompt <fixed>` in an empty temp directory with the prompt on stdin. `is_error`/non-success subtype, missing `structured_output`, non-JSON or oversized output raise ValueError with a classified message; output text is never echoed. Provider names live in `voicework/live.py`.

Anthropic mode (`--provider anthropic`, default model claude-opus-5-5) POSTs to the Messages API (`VOICEWORK_ANTHROPIC_URL`, https or loopback http) with `ANTHROPIC_API_KEY` from the environment, one forced tool `voicework_result` whose input_schema is `_schema(task)`, no other tools, no redirects. `stop_reason=max_tokens`, a missing/duplicate tool call, oversized (>2 MB) or invalid JSON raise ValueError; HTTP errors map to fixed messages without echoing the body. `available()` means a key is present, not that it works. Outputs and stored records carry `provider` = the exact mode; `codex` and `anthropic` are both live (`provider.LIVE_PROVIDERS`). `eval_cases`/`quality_cases` accept `offline|codex|anthropic`; `migrations.allow_live_provider` rebuilds an older table once with identical rows. /api/state settings add `provider_label` and `live`; capabilities add `provider_available`.

## Whole-document harness

- `GET /api/session` → `{token,provider,limits:{document_chars,output_chars}}`; obtains the mutation token without returning the corpus.
- `POST /api/context/resolve {context}` → direct routing report. It preserves explicit labels, explains canonical aliases and selected evidence/lesson counts, and offers existing contexts for deliberate selection. It does not infer a recipient from the document or choose a saved context automatically. Technical article channel aliases and bounded technical-explanation intents share matching keys; unknown channels abstain across samples, lessons and priors. Stored contexts and lesson fingerprints are unchanged.
- `POST /api/documents {context,source,controls?}` → HTTP 202 job `{id,kind,status,result?,error?}`.
- `POST /api/document-checks {context,source,text,controls?}` → HTTP 202 job with the same shape; checks an edited draft without regenerating it.
- `GET /api/documents/:id` polls a job. Status is `pending|running|complete|failed`. On completion `result` includes `checks`, `provider`, `evidence_ids`, `context_report`; rewrite results also include `text`, `warnings`, `sections`. Unknown/expired jobs return 404; busy generation slots return 429. Requests retain normal token/origin/JSON protections.

Source: nonblank Markdown or plain text, maximum 120,000 characters. Draft: maximum 240,000 characters. No truncation or rich document conversion. Structure/prose block and batch caps may reject a document below the character cap; pathological unbreakable tokens are rejected. Existing message drafts retain their 15,000-character brief and 30,000-character output limits. Controls additionally accept `register: auto|casual|professional|formal` (default `auto`). Document controls also accept `length: auto|preserve` (default `auto`). `preserve` asks the model to keep each block about as long as its source and adds a `section_lengthened` warning when a section grows by more than a quarter plus 12 characters; it suits labels, captions and short site entries.

`Provider.generate_document(context,source,controls,evidence,preferences)` returns the whole result; `Provider.check_document(context,source,text,controls,evidence,preferences)` returns checks directly. All inputs and eligible profile material are copied before background work. The report records a profile-input fingerprint and actual supplied evidence IDs. Later profile edits do not change an in-flight document. No document operation writes samples, lessons, votes or corrections.

Checks include `status`, `source_hash`, `draft_hash`, separate `content` and `voice` groups, and model-review coverage/limitations. Each group has `status: checked|review_required|not_checked` and `issues:[{severity:error|warning,code,message,section?}]`. Overall `checked` means the implemented checks completed without reporting an issue, never factual certification or personal voice accuracy. Semantic reviews compare against supplied source, not independent truth. Source/draft edits invalidate old checks; UI rechecks the current revision explicitly.

Generation preserves protected structural blocks locally and validates exact ordered generated block IDs. Incomplete/invalid generation fails without accepting a partial draft. Deterministic content checks compare source/draft invariants; Codex additionally reviews bounded source/draft windows for meaning and applicable voice guidance. A failed or incomplete review retains the draft with explicit unavailable checks and requires review. Offline mode retains the exact source and marks semantic/voice checking unavailable.

Jobs share the existing two generation slots. At most 16 job results are cached in memory; completed results expire after one hour and older completed jobs may be evicted earlier. Refresh can resume polling while the server remains running. Restart loses jobs, not browser-saved source/edits or database records. The server does not persist document jobs to SQLite. A job can require up to 12 generation and 16 review calls; per-call timeouts and batch caps bound work.

`python3 -m voicework.harness --request request.json --output result.json` is a loopback-only client; `--check` selects checking, `--request -` reads stdin. Result files are exclusive new files created mode 0600. Exit 0 = completed checks without reported issues, 3 = result needs review, 2 = failure. It never auto-saves generated text as training or sends the text to another recipient. Client timeout stops waiting, not the already-running server job.

## Source-relative meaning of individual edits

`edit_spans.py` aligns exact sentence spans, then separates local changes at stable context/clause boundaries. `meaning.py` requests an assessment for each edit, including changes without negative/modal words. Multiple edits within one paragraph or a sentence can receive different verdicts. Scattered sentence reconstruction and sentence splits/joins are explicitly labeled `assessment_scope: combined`; the app does not claim to separate dependent rewrites into independent word changes. Bounded review still covers the whole source/draft, not only these candidates.

Each request contains `change_id`, `section`, zero-based `unit_index`, exact `source_quote`/`draft_quote`, `source_context`/`draft_context`, and `source_range`/`draft_range` as Python Unicode character offsets within that unit. Quotes/context are extracted locally; the model cannot invent or replace them. The provider returns `meaning_checks:[{change_id,verdict:preserved|changed|uncertain,dimension,reason}]`. Dimensions describe the actual semantic difference: polarity, scope, actor, time, condition, claim_strength, commitment, quantity, attribution or content; preserved requires none. Reasons are nonempty and at most 1,000 characters. Legacy dimensionless assessments remain parseable and receive neutral labels, never a label inferred from a lexical trigger.

Content findings additionally include `change_ids:[...]`, with unique IDs belonging to the current review batch, or [] for an independent/unattributed concern. The model reports covered differences in the edit assessments instead of repeating them as independent issues. Unknown or repeated links/assessments invalidate the review; missing assessments remain unreviewed. Voice issues retain their separate schema and role.

`checks.meaning_changes` contains the individual exact spans, context, ranges, assessment_scope, verdict, dimension, label, reason and reviewed status, plus bounded-coverage notices. `content.issues` contains consolidated alerts. A group has `change_id`, meaningful `label`, original maximum `severity`, and `evidence` containing attributed supporting signals. `content.signals` retains the underlying deterministic, semantic-review and edit-assessment signals with their origins and edit links. Only explicit model links or validated local numeric/marker differences attribute signals to edits; sharing a section or similar wording never authorizes merging. Distinct edit IDs remain distinct even when they use identical words. Independent or cross-edit findings stay visible. A preserved assessment conflicting with an independent semantic finding yields one unresolved conflict alert. Numeric errors survive even when a model says meaning is preserved. No protected error is erased or downgraded.

The UI shows one alert per attributed edit, expandable supporting checks, and separate before/after spans under **Individual edits & meaning**. Context is available in a disclosure. Harmless edits retain their own preserved assessments beside changed claims. Lexical negation/modal counts remain diagnostic evidence rather than the label for the actual problem.

Edit alignment applies inside changed sentence groups even when sentence counts differ. Local token hunks split at stable phrases of at least three words, unchanged clause/sentence boundaries, or a stable word followed by a rewritten clause boundary. A passage-wide edit-density rule cannot swallow independent changes. Changed-token phrase relocation links keep related removed/reinserted wording together; function-word pairs alone do not create those links. Multiple related hunks are labeled `combined`, never claimed to be independent semantic atoms. Each exact range retains the complete aligned passage as context; model review checks moved claims in that context and does not transfer a neighboring meaning change to a harmless local rephrase. Bounded window alignment can remain ambiguous, and uncertainty must stay visible.

All detected edit candidates are planned with globally unique IDs and their original exact spans, ranges and source/draft context. At most 24 assessments and 24,000 combined context characters are requested per provider call, not per document. Long candidates use their complete bounded review-window context; a context-budget overflow starts another call rather than dropping an edit. An inconsistent over-budget plan fails explicitly. Existing document and full-unit window limits still apply.

The first call for each source/draft window remains `document_review`, with general content/voice review, applicable anchors and its first edit group. Its compact `meaning_change_catalog` contains IDs, sections, unit indices and exact ranges for all edits in the window, so independent findings can explicitly link to later-batch edits without duplication. Its `meaning_checks` may assess only the current requested group. Subsequent `document_meaning` calls return only `{meaning_checks,warnings}` under a strict schema: general content/voice findings cannot recur there. They use the same frozen guidance and complete source/draft units; style guidance never permits factual changes. Unknown, repeated or wrong-batch assessment IDs invalidate the call. Missing verdicts remain unreviewed. Full-unit completion requires every assigned call to succeed; partial failure cannot clear a global lexical alert.

`review` reports `edit_batches_total`, `edit_batches_completed`, `calls_total` and `calls_completed` alongside full-window counts. `meaning_changes` reports `total`, `reviewed` and `unreviewed`; all planned candidates stay in `checks`, including missing/failed assessments. The complete marker-token difference must be accounted for by exact edit spans before attribution. Completed preserved judgments clear lexical negation/modal alerts while retaining their nonblocking supporting signals; a changed/uncertain assessment or independent conflict stays actionable. Unaligned marker coverage remains an explicit `meaning_review_limited` concern; unknown coverage cannot become a clean result. Numeric/protected guards remain independent. Editing source, draft, context or controls invalidates earlier checks. No assessment changes preferences, inference approvals, votes, samples or article text.


## Voice findings and optional style suggestions

The native review schema requires every voice issue to include `classification: preference_violation|style_suggestion|uncertain`, at most six `preference_ids` from the supplied `voice_reference_catalog`, exact `source_quote`/`draft_quote` (empty for absence or uncertain alignment), and `basis` explaining the preference conflict or optional rationale. Catalog IDs resolve only to the frozen, context-selected guidance and current controls/request. Pending/inactive evidence is never introduced by classification. The catalog points to existing guidance without duplicating raw samples or intake records.

A claimed violation needs a quoted passage and an applicable explicit lesson/current instruction. References to learned tendencies or identity goals alone can support only an optional suggestion. Scope, exceptions and whether a quality survives in surrounding prose remain semantic judgments; the app validates provenance and keeps the judgment reviewable, not mathematically proved. Unknown references or invented quotes invalidate the review. Legacy responses remain readable as uncertain findings and cannot trigger revision.

`checks.voice.issues` contains conflicts and uncertainty; `checks.voice.suggestions` contains optional improvements with `severity: suggestion`. Both retain classification, quotes, basis and resolved `preference_refs`. Suggestions alone do not set `review_required` or trigger automatic revision. Independent semantic safeguards and unavailable checks remain explicit. No learning is saved by classification or rechecking.

Aspect checks use the same classification and evidence fields; preserved/overridden requires classification `none`, and uncertain requires `uncertain`. A flattened quality can be a suggestion or a conflict. A conflict must reference its anchor lesson. Missing classifications are uncertain. Only a classified, grounded preference violation can trigger the one bounded repair. The repair cannot be accepted while a violation or unresolved voice assessment remains; optional suggestions do not prevent acceptance. The UI separates optional suggestions from violations and exposes the reasoning and supplied guidance. Existing results without classifications are displayed as unclassified earlier assessments until rerun.

## Evidence coverage and review status

`checks.coverage_notices:[{code,message}]` describes evidence supplied to this review, separate from content/voice findings and unresolved `warnings`. Notices are generated locally from the frozen inputs, even if the model returns no codes. The supported codes are `no_authored_examples` and `no_voice_guidance`. Provider `document` and `document_review` schemas require `coverage_notice_codes` as an array of these codes, selected only from the supplied `coverage_notice_catalog`. Unknown, duplicate, malformed or inapplicable codes invalidate the response. Models cannot supply arbitrary notice messages or turn a passage-level finding into a coverage notice. Legacy responses without codes remain parseable; free-text warnings are never downgraded by word matching.

Missing authored examples alone does not make a valid review fail when applicable guidance is supplied. Coverage notices and optional suggestions cannot set `review_required` or trigger repair. Group statuses describe that group's findings and review availability; unresolved warnings remain visible separately and require review of the overall result. Without applicable voice guidance, `voice.status` is `not_checked` and missing guidance appears as a notice, not a preference violation. With no actionable findings or warnings, an incomplete group makes the overall status `not_checked`. Invalid/incomplete provider reviews, omitted edit assessments, numeric/protected-content failures, voice uncertainty and unresolved generation caveats retain their safeguards. The UI labels completed checks, evidence coverage, optional suggestions and unresolved review concerns separately. Earlier stored results are not silently reclassified; rerun checks for current statuses. This changes no learning or evidence approvals.


## Register and personal perspective

Native voice findings and aspect checks require `voice_effects:{register:{verdict,reason},perspective:{verdict,reason}}`. Register verdicts are `fits_context|over_formal|over_casual|mixed|not_applicable|uncertain`; perspective verdicts are `preserved|reduced|shifted|not_present|uncertain`. Each independent reason is nonempty and at most 1,000 characters. Unknown, missing or extra fields within a supplied assessment invalidate review. Legacy findings without the field remain readable but explicitly lack separate assessments. Exact quote, context and preference-grounding safeguards remain in force.

Register is assessed against applicable guidance and current controls. Perspective concerns whether a particular source observation, expectation, reaction or judgment survives the affected change in context. Formal vocabulary does not imply lost viewpoint; first person alone does not prove it survives; an impersonal sentence can preserve it through context. Both qualities can be affected. Neighboring edits are assessed separately. Classification as violation, optional suggestion or uncertainty remains a separate judgment with the same evidence requirements. App-generated summaries label the two effects independently and expose their reasons. The model's natural-language judgment is not mechanically verified. Repair receives the assessments and must not add personal claims to fix register. No preferences, identity approvals or writing are saved by review.

### Automatic authored retrieval across contexts

`sample_relevance.py` defines versioned, deterministic retrieval assessments; it does not call a model or infer authorship. The existing exact/alias context match ranks first, with a recognized-purpose conflict guard. Otherwise transfer requires recognized source and target purposes, compatible audience labels and explicit register/privacy/relationship/stakes boundaries, a writing cue in the first 2400 characters actually supplied, and at least two topic signals. Technical/research targets use a declared technical/product vocabulary; other contexts require shared topic words. Explanation targets may draw on mechanism/sequence, question framing and caveated alternatives. Updates and review requests keep their own purpose. Unknown labels or weak evidence abstain. This is bounded lexical/structural relevance, not general semantic retrieval; false positives and missed useful writing remain possible. Source context is provisional where labeled so, never rewritten by selection.

`select_samples` applies authorship, holdout and AI-addressee gates before reading text, deduplicates identical normalized supplied excerpts, gives explicit references priority, and caps total examples at six and automatic transfers at three. Its `automatic_selections` report includes IDs, original context, method version, reasons, the proposed aspect, supporting excerpt, topic terms and limitations. Rejected text is never placed in the report or prompt. Aggregate omission reasons distinguish provenance, purpose, audience/boundary, weak evidence, duplicates and budget. Full selections are copied and frozen with the draft. The provider recomputes automatic assessments and checks exact target scope/provenance before prompt construction. `automatic_transfer` is labeled a provisional retrieval inference, never a user-approved preference; it cannot establish a mandatory voice violation. Document coverage remains separate from writing findings. Quality/profile comparisons retain the same selected evidence rather than applying the old strict matcher again.

`POST /api/context/resolve`, `/api/documents` and `/api/document-checks` also accept `excluded_sample_ids`, a list of at most 100 unique IDs (each a nonblank string up to 100 characters). Exclusions apply to that request/document only. A reference cannot be both explicitly selected and excluded. Browser exclusions persist, invalidate prior checks and clear when context changes. Preview displays reasons and exclusion controls; completed results preserve the recorded reasons. Source snippets are rendered as text. ### Article-scoped kept wording decisions

`POST /api/document-decisions` accepts `{source,text,context,controls,suggestion,reason}` under the existing origin/token checks. This is an explicit user action, not an automatic consequence of review. `suggestion.classification` must be `style_suggestion`; both nonempty quotations must occur once, each wholly inside a paragraph. Codes, message, basis, preference IDs and reason are bounded and validated before persistence. This endpoint records a user-submitted optional choice, not proof of a model verdict or an authorship claim. It can never suppress a non-optional finding.

Two additive SQLite tables, `document_keep_decisions` and `document_keep_events`, store the original source hash, title, validated context and controls, paired quotes, surrounding paragraph hashes, suggestion metadata, reason, status and timestamped keep/revoke/restore history. A duplicate active keep is idempotent; repeating a revoked keep restores the existing record. There are at most 100 records per source; returned history is limited to the latest 100 events. No existing training/profile tables or profile export are changed. These private records are independent of general language lessons, preferences, identity and authored samples.

`POST /api/document-decisions/resolve` accepts `{source,text,context,controls}` and returns records for that exact original source with `applicable|context_changed|passage_changed|revoked`, reasons, history and a snapshot hash. A changed source starts a separate document scope. `POST /api/document-decisions/:id/revoke {}` is idempotent and preserves history. Missing records return 404; malformed actions fail before a write.

Document jobs freeze these records separately from writing guidance at request start. Before each complete-document review, `classifier_context` recomputes scope against the actual source, draft, context and controls. Active records with matching source/context/controls enter `document_review.article_keep_decisions`: `unchanged_passage` gives the specific accepted optional objection priority over its broad lesson; `changed_passage` supplies historical context without approving current text. The projection contains the decision ID, paired quotations, prior objection, preference references and user reason, not profile history or a general rule. Source anchors must remain unique and unchanged. Other articles, changed context/controls and revoked records are excluded. The voice reviewer must distinguish the accepted tradeoff from independent preference conflicts and assess meaning from the source regardless of any choice. Harmless rephrasing of that tradeoff alone is not a new mandatory violation. The model may omit repeat advice or return its canonical optional finding for acknowledgement; model judgment remains reviewable and is not mechanically guaranteed.

If any scoped keep choice or exact wording correction is supplied, `document_review` receives an empty `meaning_change_requests` array; all planned edit batches, including the first, run through separate `document_meaning` calls without either kind of instruction. The complete-document review still reports additional content concerns against the full edit catalog; these cannot erase independent edit assessments. Coverage counters include the additional call per review batch with edits, and failures remain incomplete rather than accepting a clean voice result. With no supplied choices, the existing combined first call is retained.

Decision context is bounded at 24,000 serialized characters; exceeding the limit fails review visibly instead of silently dropping choices. It is passed separately from the frozen general guidance, so the existing guidance hash and profile fingerprint remain stable. `checks.document_decision_review` records supplied choice IDs/scopes, a separate context hash and review status. The UI reports the count and distinguishes historical context. A separate narrow projection now enters initial and repair generation as described below. Decisions never enter supplemental `document_meaning` calls, general learning, authored samples or profile exports. Repair reviews recompute scope on their actual output, so stale applicability cannot authorize changed wording.

All native meaning and voice checks still run. Afterwards, only a `style_suggestion` with the same exact source/draft quotations and preference-reference set inside the unchanged accepted paragraph is moved from `voice.suggestions` to `voice.accepted_suggestions`. Model labels and message wording need not be identical. Changed passages, duplicate quotes, changed context/controls, different references, nearby edits and different quotation boundaries do not match. Content findings, voice violations, uncertain assessments, coverage, review availability and status are untouched; there is no automatic downgrade of a classifier's remaining violation. Native diagnostic metadata remains attached to the accepted choice with its decision ID and reason; `checks.document_decisions` records the frozen scope and history. Generated documents are matched against their actual resulting passages before acknowledgement.

The browser offers keep only for current optional findings with both quotes, provides saved-scope/history review and undo, and invalidates previous or in-flight checks after a keep/undo action. Source and draft text never change through these actions. Stored review results retain their decision snapshot; use **Review saved article decisions** to refresh current database state and rerun checks after changes.

### Exact article wording and generation compliance

`POST /api/document-wording {source,context,controls,source_quote,wording,reason}` records an explicitly requested correction or preservation. Quotes and wording are bounded at 1,000 characters; the reason is required and bounded at 1,000. The source quote must be unique, wholly within one prose block, and anchored to its original paragraph. Required wording cannot already occur outside that source selection. Empty values, controls, headings/code/table targets and ambiguous anchors fail before persistence. Equal source/required wording means preserve the phrase; this is not a learned quality or an authored sample.

`document_wording_corrections` and `document_wording_events` are additive private SQLite tables. Records bind to the exact source hash, normalized six-field context, controls and source paragraph. These endpoints use the usual origin/token guard. No learning, identity, quality vote or existing keep record changes. The UI supports creation, review and undo; saves invalidate previous/in-flight checks without editing the article.

Jobs freeze both record sets separately from writing guidance. `instruction_plan` revalidates source/context/controls/status/anchors; it does not trust stored applicability. Kept optional decisions project only their paired quote and narrow reason; corrections project the exact requested wording. Both map to source prose block IDs. Revoked/wrong-context records are skipped with reasons. Conflicting overlapping requirements, protected/cross-boundary targets and more than 24,000 serialized instruction characters fail rather than silently dropping instructions. No article-title or fuzzy identity match is used; replacing the source starts a new article scope.

Every initial and targeted-revision `document` call receives only instructions for its target blocks in `article_wording_instructions`. The provider must retain/produce each required quote exactly once in its specified block and remove the replaced original when it is not part of the required wording. Failed retries preserve a complete provider draft and visible warnings. A voice revision that still loses required wording is rejected in favor of the initial complete draft and its findings. Generation attempts remain auditable; no attempt changes the profile.

`checks.article_wording` reports a separate instruction/context hash, applied/skipped IDs, literal statuses, reasons and attempt outcomes. Missing, duplicate, wrong-block and leftover replaced wording cannot yield a clean generation compliance result. Full-document uniqueness is checked after assembly. Literal compliance never clears semantic/voice findings or unavailable reviews. Standalone rechecks retain the earlier semantics of a kept optional choice: changed accepted wording is historical context, not a new exact-word violation. All individual meaning calls remain free of either kind of article instruction. Profile/guidance hashes remain independent of the article instructions.
